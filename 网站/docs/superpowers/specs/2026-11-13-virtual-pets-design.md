# TOM 与皮皮共享虚拟宠物设计规格

日期：2026-11-13  
状态：已实施；2026-11-17 按用户要求将生产模型替换为 Mesh2Motion CC0 蓝猫与黄色犬  
范围：情侣网站新增 `/pets` 页面、两只共享宠物、照片重建模型、养成状态和互动

## 1. 目标

为一对情侣提供共同照顾 TOM 和皮皮的 3D 虚拟宠物空间。两只宠物共享同一份服务器状态，无论谁打开网站，看到的饥饿度、清洁度、精力和亲密度都一致。宠物不会因长时间未登录而死亡或永久失去，核心体验是陪伴、照顾和记录。

成功标准：

- TOM 是可识别的灰色英短：圆脸、短密灰毛、金色眼睛、粗尾、灰色肉垫。
- 皮皮是可识别的浅黄褐色梗犬混血：垂耳、浅色口鼻与眉毛、黑色鼻头、白色胸腹和爪尖、粗硬蓬松毛。
- 两者均由真实照片参与重建，不使用像素宠物、表情符号或纯程序几何硬拼外观。
- 模型可播放待机、进食、洗澡、睡觉、玩球、逗猫和亲近动作。
- 宠物状态永久保存在 SQLite，刷新和服务器重启后不丢失。
- 桌面端与手机端均可流畅查看和互动。

## 2. 视觉基准

### TOM

- 毛色为冷调蓝灰，短而密，边缘有细柔高光。
- 头部圆润，脸颊饱满，耳朵中等大小，耳内为深灰粉色。
- 眼睛为琥珀金色，瞳孔可随光线变化。
- 体型偏结实，尾巴较粗，四肢短而稳。
- 肉垫为深灰褐色，保留足部短毛边缘。
- 动作气质偏安静，亲近时眨眼、缓慢蹭头、轻摆尾巴。

### 皮皮

- 主体毛色为金黄色至浅黄褐色，局部有较深的耳根和背部渐变。
- 口鼻、眉毛、胸口和爪尖偏奶油白，胡须明显。
- 毛发粗硬蓬松，嘴边、耳朵和腿部保留梗犬式不规则轮廓。
- 鼻子纯黑，眼睛为深棕黑色，垂耳一高一低。
- 体型中小，胸口宽，站立时四肢略外八。
- 动作气质偏热情，亲近时快速摇尾、吐舌喘气、前肢趴低。

## 3. 模型制作流程

所有照片仅在本机处理，不上传到第三方生成网站。大型重建工具不进入网站运行时。

1. **照片预处理**
   - 从用户提供的照片中裁切清晰主体，移除人物、家具、地毯和其他私密背景。
   - TOM 以正面近景、左右侧面、趴卧和爪部近景为主要参考。
   - 皮皮以站立全身、侧面、正面笑脸、湿毛、蜷睡、爪部和玩磨牙棒照片为主要参考。
   - 不把原始生活照作为网站资源或纹理直接公开。

2. **静态网格重建**
   - 使用 MIT 许可的 TripoSR 本地推理，输出带顶点颜色或烘焙纹理的 GLB。
   - 运行环境使用独立工作目录和兼容 CUDA 的 PyTorch；本机 RTX 5060 8GB 满足 TripoSR 的约 6GB 显存需求。
   - 对耳、口鼻、眼睛、尾巴和四肢进行二次清理，避免照片背景被误识别为身体。

3. **真实感材质**
   - 使用照片颜色校准生成 2K PBR 基础色、粗糙度和法线纹理。
   - TOM 使用短密毛的壳层毛发和柔和掠射高光。
   - 皮皮使用更长的壳层毛发、明显胡须和粗糙度变化。
   - 眼睛、鼻头、肉垫分别使用独立材质，避免整只宠物变成同一种塑料质感。

4. **骨骼与动画**
   - 使用 MIT 代码、CC0 动画资源的 Mesh2Motion 为静态网格自动绑定宠物骨架。
   - 使用 CC0 的 Quaternius 猫狗动画作为动作拓扑参考，并通过重定向生成：
     `Idle`、`Walk`、`Eat`、`Bath`、`Sleep`、`Ball`、`Teaser`、`Affection`、`TailWag`。
   - 最终 GLB 内嵌纹理和动画，浏览器只加载优化后的资产。

5. **模型验收检查点**
   - 先交付 TOM 和皮皮的静态模型，不进入页面整合。
   - 每只宠物提供正面、左侧、右侧、背面的 3D 转台预览和可拖动本地 GLB 预览。
   - 只有用户确认外观后，才开始骨骼动画与 `/pets` 页面实现。

### 风险与回退

照片重建可能把背景、衣物或遮挡误识别为身体。如果本机推理在人物、家具背景下无法得到可接受的主体，则先清理照片后重试，不直接接受错误网格。

TripoSR 生成的是静态网格，自动绑定后可能出现嘴、耳朵或尾部权重错误。动画制作时以可读性和自然度为验收标准，不为保留错误网格而牺牲动作。

若本地重建或自动绑定被硬件、模型兼容性阻塞，必须向用户说明并取得明确许可后才能使用外部生成服务。未经许可不上传用户照片。

## 4. 页面体验

新增导航项「宠物」，桌面端放在音乐和后台之间，手机端增加对应底部标签。页面路由为 `/pets`，和相册、时间线共用现有相册密码会话。

视觉方向：

- 暖纸色与浅木色客厅，延续当前 Quiet Luxury 玻璃质感。
- 场景包含双人沙发、地毯、猫爬架、狗窝、水碗、食盆、玩具篮和浴盆。
- TOM 默认在猫爬架或地毯上，皮皮默认在狗窝或沙发旁。
- 点击宠物切换当前照顾对象，非当前宠物继续低频待机。
- 状态信息使用克制的小型玻璃浮层，不遮挡宠物。

桌面布局为左侧 3D 场景、右侧宠物资料与状态；手机端使用纵向场景和底部操作面板。所有按钮保留当前珠光液态金属体系。

## 5. 互动规则

宠物有四项状态，范围 0–100：

- **饱腹**：随现实时间下降，喂食恢复。
- **清洁**：随现实时间下降，洗澡恢复。
- **精力**：清醒时缓慢下降，睡觉恢复。
- **亲密度**：照顾和互动提升，长时间无互动缓慢下降。

状态由服务器按时间戳惰性结算。页面关闭后仍会随时间变化，所有数值始终限制在有效范围。

互动：

| 互动 | TOM | 皮皮 | 主要效果 |
| --- | --- | --- | --- |
| 喂食 | 低头进食、舔嘴 | 快速吃、摇尾 | +饱腹，少量 +亲密度 |
| 洗澡 | 炸毛、甩水、舔毛 | 甩水、抖毛、吐舌 | +清洁，少量 -精力 |
| 睡觉 | 蜷睡、耳朵轻动 | 侧躺、呼吸起伏 | 持续恢复精力 |
| 玩球 | 观察、扑球 | 追球、叼回、邀玩 | +亲密度，-精力，少量 -饱腹 |
| 逗猫棒 | 蹲伏、追踪、扑抓 | 只观察，不播放猫动作 | +亲密度，-精力 |

每只宠物同一时间只播放一个主动作，动画 3–8 秒。服务端对同一宠物的操作设置 5 秒最小间隔，防止误触和重复提交。互动不会造成死亡或永久负面状态。

## 6. 成长设计

成长以领养后的真实天数和累计照顾点共同决定，只改变气质和细微体型：

| 阶段 | 条件 | 表现 |
| --- | --- | --- |
| 来到身边 | 第 0–2 天 | 基础体型，动作更谨慎 |
| 慢慢熟悉 | 第 3–13 天 | 体型约 +1.5%，主动靠近频率提高 |
| 安心相伴 | 第 14–44 天 | 体型约 +3%，毛发更有光泽，睡姿更放松 |
| 长久家人 | 第 45 天起 | 体型最多 +4%，保留稳定成熟动作 |

体型变化封顶，不使用夸张升级形态。成长阶段升级时生成一条共享纪念事件。

## 7. 数据与接口

新增 SQLite 表：

### `pets`

- `id`
- `slug`：`tom`、`pipi`
- `display_name`
- `adoption_date`
- `satiety`
- `cleanliness`
- `energy`
- `affection`
- `care_points`
- `sleeping_since`
- `last_simulated_at`
- `current_pose`

### `pet_events`

- `id`
- `pet_slug`
- `action`
- `summary`
- `created_at`

API：

- `GET /api/pets`：返回两只宠物结算后的状态、成长阶段和最近 30 条事件。
- `POST /api/pets/:slug/action`：接受 `feed`、`bath`、`sleep`、`ball`、`teaser`，校验宠物允许的动作后更新状态。
- `POST /api/pets/:slug/wake`：结束睡眠。

页面和 API 复用相册鉴权。未解锁时显示与相册一致的锁屏，不暴露宠物状态。动作字段采用固定允许列表，所有数值在服务端计算。

## 8. 错误处理与性能

- GLB 加载失败时显示对应宠物的高分辨率转台静态图，并提示“3D 场景暂时不可用”，仍可查看状态但不伪造互动动画。
- 动画开始、结束和模型加载完成前禁用重复按钮。
- 交互失败时回滚 UI 乐观状态并显示错误提示。
- 减少动态模式下关闭持续漂浮和环境粒子，互动直接切换到结束姿态。
- 两只 GLB 合计不超过 20MB，单张纹理不超过 2K，DPR 上限 1.75。
- 页面离屏时暂停动画循环，回到可视区后恢复。
- 不依赖外部 CDN，模型、纹理和动画全部本地部署。

## 9. 验收标准

- TOM 和皮皮的静态模型先通过用户视觉确认。
- 毛发、眼睛、鼻头和肉垫不是同一材质，近距离不出现明显像素块。
- 三种以上互动动画在桌面端与手机端均可完整播放。
- 两只宠物状态在刷新、关闭浏览器和重启服务后保持。
- 相册密码会话能保护宠物页面和操作。
- 服务器时间结算不会产生负数、超过 100 或重复事件。
- 手机 390×844 无横向溢出。
- 减少动态模式、WebGL 不可用和 GLB 加载失败均有可用降级。
- 现有倒计时、相册、时间线、音乐、3D 爱心和页面转场测试继续通过。

## 10. 实施里程碑

1. 建立独立本地图片重建环境，处理 TOM 和皮皮的照片。
2. 生成静态 GLB、PBR 材质和四向转台，交付给用户确认外观。
3. 自动绑定骨骼，制作并验收九类动作。
4. 新增宠物数据库、状态结算、鉴权和 API。
5. 实现 `/pets` 3D 场景、导航、状态面板和互动。
6. 完成移动端、持久化、失败降级和全站回归。
7. 更新 README、模型来源和许可说明。

## 11. 非目标

- 不做多人账号、繁殖、战斗、商店或付费系统。
- 不做宠物死亡、永久走失或高惩罚饥饿机制。
- 不使用像素素材、表情符号宠物或视频贴片伪装成 3D。
- 不把用户原始生活照公开为网站资源。
